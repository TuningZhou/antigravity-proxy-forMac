## 🛠️ 关键技术修复与演进 (Changelog & Technical Improvements)

### 1. 彻底根治 Electron `posix_spawn` 自递归崩溃 (SIGBUS)
- **原因剖析**：`posix_spawn_fn` 与 `posix_spawnp_fn` 拥有相同的函数指针签名，旧版泛型模板的局部 `static` 缓存导致两个函数共享了同一个函数指针。Electron 启动初始化时优先调用 `posix_spawnp`（缓存了 `libsystem_c` 地址），随后进入 `my_posix_spawn` 误调用该指针，又被内部包装重定向回被 interpose 的 `posix_spawn`，形成 4 秒后必定发生的无限递归与 SIGBUS 堆栈爆裂。
- **解决方案**：重构 Hook 指针分发机制，每一个 `Real*()` 分配专属函数级 `static const` 指针，模板剥离全局缓存职责，彻底杜绝串号递归。

### 2. 弃用 `dlsym(RTLD_NEXT)`，引入权威 Mach-O 符号表直接解析
- **原因剖析**：在现代 macOS 内核中，一旦动态库使用 `__DATA,__interpose` 对某符号进行了拦截，在钩子内部调用 `dlsym(RTLD_NEXT)` 获取原函数时，dyld 会回环返回钩子自身地址，导致 `my_xxx -> RealXxx -> my_xxx` 死循环。
- **解决方案**：实现 `ResolveSystemSymbol`，直接遍历 dyld 已加载镜像列表的 Mach-O 符号表（`nlist_64`），仅匹配 `N_SECT` 真实定义段，并按权威库进行精确归属：
  - `connect` / `close` / `execve` / `posix_spawn` $\rightarrow$ `libsystem_kernel.dylib`
  - `posix_spawnp` $\rightarrow$ `libsystem_c.dylib`
  - `getaddrinfo` / `freeaddrinfo` / `gethostbyname` $\rightarrow$ `libsystem_info.dylib`
  彻底规避了重导出桩与未决引用的误判。

### 3. Agent 沙箱自动穿透 (`Seatbelt / sandbox-exec` 解除)
- 识别并剥除针对 `language_server_macos_arm` 的 `sandbox-wrapper.sh` 包装链，绕过 macOS Seatbelt `(deny network*)` 对环境变量的强制洗涤，使 Agent 智能体后端无缝继承 SOCKS5 代理。

### 4. 独创“官方原件 + 代理副本 (TUN)”双轨共存安全设计
- **官方原件零污染**：官方 `Antigravity.app` 一个字节都不修改，完整保留 Google 原始签名与 Hardened Runtime 完整性。
- **独立代理副本**：首次启动在同级目录生成 `Antigravity IDE TUN.app`，仅对副本打上本地 ad-hoc 签名补丁增加动态库注入许可；原件与副本共享配置和登录凭据。随时可通过删除副本实现 100% 干净卸载。

## 🚀 快速上手指南（免编译 3 步启动）

### 第 1 步：解压并放置
下载 `antigravity-proxy-v2.4-mac-universal2.zip` 解压后，将 `Antigravity-Proxy-macOS` 文件夹移动到用户主目录应用程序中（**推荐路径**：`~/Applications`）。
> ⚠️ **注意**：请避免直接放在“桌面 (Desktop)”、“下载 (Downloads)”或“文稿 (Documents)”内，因为 macOS TCC 隐私保护会拦截提权操作并报错 126。

### 第 2 步：配置代理端口
双击运行 `Antigravity-Proxy.command`（首次打开请在访达中 **右键 → 打开**）：
- 在出现的交互菜单中按 **3**，将 `config.json` 中的 `proxy.port` 改为本机代理软件的监听端口（如 Clash 为 `7890`、V2RayU 为 `10808`、Surge 为 `6153`），保存并关闭。

### 第 3 步：一键启动
- 在启动器菜单中按 **1**，启动器会自动完成原件副本克隆并注入启动。
- 随后在 IDE 登录窗口中点击 **Sign in with Google**，浏览器授权成功后即可正常进入！
